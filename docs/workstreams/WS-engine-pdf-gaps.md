# WS-engine-pdf-gaps — three PDF MVP checks (owner: kilo)

Scope source: `docs/superpowers/specs/2026-11-25-mvp-scope-design.md`.

**Own:** new files `packages/engine/src/checks/input-validation.ts`, `firewall-rules.ts`, `incident-playbook.ts`, their tests in `packages/engine/test/<id>.test.ts`, and the array in `packages/engine/src/checks/delivery.ts` (add the three there). Do not edit `types.ts`, `registry.ts`, `diffGuard.ts`, `security.ts`, `secrets.ts`, `rate-limit.ts`, `security-headers.ts` or anything outside `packages/engine`.

Copy the shape of `packages/engine/src/checks/health-endpoint.ts` and its test. Detectors are pure functions over `ctx.repo.files`. Fixers are deterministic, recompute from `ctx.repo`, return `class: "additive"`, and must pass `guardPatch`. Never touch owner lines except a single inserted line where stated. Code-pattern scans only read `.js .ts .mjs .cjs .jsx .tsx` files and skip paths containing `test/`, `tests/`, `__tests__` or ending `.test.*` / `.spec.*`.

1. `input-validation` (high, template, C-security). Fail when an Express route handler reads `req.body` or `req.query` and the same file never calls a validation helper (`validate(`, `.parse(`, `.safeParse(`, `.validate(`, `celebrate(`, `checkSchema(`, `body(`). One finding per file, line = first `req.body`/`req.query` line. Fix: create `middleware/validate.js` only (do not edit routes): a dependency-free CommonJS helper `validate(shape)` where shape maps field names to `"string" | "number" | "boolean" | "email"`, returns Express middleware that checks `req.body` against it and responds `400 {error:"invalid input", field}` on the first mismatch, else `next()`. Explanation tells the owner to add `validate({...})` to each route that reads input, and shows one example line. The check passes when `middleware/validate.js` exists or a validation call is found in that file, so re-detect after the fix returns `[]`.
2. `firewall-rules` (medium, template, C-security). Fail when the repo has no `infra/security-group.yaml` and no file containing `AWS::EC2::SecurityGroup` or `ufw `. Fix: create `infra/security-group.yaml` (CloudFormation: one `AWS::EC2::SecurityGroup` with a `VpcId` parameter, ingress TCP 443 and 80 from `0.0.0.0/0`, no port 22, egress all) and `infra/ufw.sh` (`#!/bin/sh`, `set -e`, `ufw default deny incoming`, `ufw default allow outgoing`, `ufw allow 80/tcp`, `ufw allow 443/tcp`, a comment that SSH stays closed and how to open it for one IP, `ufw --force enable`). Explanation says Siidekick never applies these; the owner reviews and runs them.
3. `incident-playbook` (low, auto, B-monitoring). Fail when no `SECURITY_PLAYBOOK.md`, `INCIDENT*.md` or `SECURITY.md` exists (case-insensitive, any directory). Fix: create `SECURITY_PLAYBOOK.md` with five headed steps (Detect, Contain, Eradicate, Recover, Review), each 3–5 concrete bullets for a small Node/Express site (rotate keys, check logs, redeploy from git, notify users, write what happened). Use the repo name from `package.json` if present.

Tests per check: failing fixture, clean fixture, fix → `guardPatch` ok → `applyPatch` → re-detect `[]`. For input-validation also: a file under `test/` reading `req.body` is ignored; a file with `.safeParse(` passes.

Done when `npx vitest run packages/engine` passes and `npx tsc -p packages/engine/tsconfig.json --noEmit` has no errors. Tests in `security*`, `dependency-audit*` or `auth-on-endpoints*` belong to another worker running at the same time; if they fail, note it in your report and do not touch them.
