# WS-deploy-pitch — Educate-account deploy + pitch docs (owner: copilot)

Scope source: `docs/superpowers/specs/2026-11-25-mvp-scope-design.md`. Read `README.md`, `docs/ROADMAP.md` and that scope doc before writing anything.

**Own:** `infra/template.yaml`, `infra/README.md`, new `scripts/deploy.sh`, new `docs/pitch/DEMO_SCRIPT.md`, `docs/pitch/PITCH.md`, `docs/pitch/SUBMISSION.md`. Edit nothing else.

1. `infra/template.yaml`: the team uses an AWS Educate / Learner Lab account, which cannot create IAM roles. Add parameter `ExistingRoleArn` (String, Default `""`, description: ARN of the lab's pre-made role, e.g. LabRole). Add condition `UseExistingRole` (ExistingRoleArn not empty). On `ApiFunction` set `Role: !If [UseExistingRole, !Ref ExistingRoleArn, !Ref AWS::NoValue]` and `Policies: !If [UseExistingRole, !Ref AWS::NoValue, <the existing policy list>]`. Keep every other resource and output unchanged. Keep the YAML valid (sam and cfn-lint are not installed; check indentation by hand and with `node -e` + a YAML-free sanity read).
2. `scripts/deploy.sh` (`#!/usr/bin/env bash`, `set -euo pipefail`): checks `aws` and `sam` exist and prints install hints if not; builds engine, runs `npx tsx scripts/bundle-demo.ts`, builds api and web (`npm run build -w <pkg>`); `sam build -t infra/template.yaml`; `sam deploy` with stack `siidekick`, `--capabilities CAPABILITY_IAM`, `--resolve-s3`, and `--parameter-overrides CloudFrontDomain=$CLOUDFRONT_DOMAIN ExistingRoleArn=$ROLE_ARN` where `ROLE_ARN` defaults to `arn:aws:iam::<account>:role/LabRole` built from `aws sts get-caller-identity`; then reads stack outputs and runs `aws s3 sync apps/web/dist s3://<BucketName> --delete`. No secrets in the script; credentials come from the AWS CLI profile. `chmod +x` is done by the lead, not you.
3. `infra/README.md`: add an "AWS Educate / Learner Lab" section (LabRole, session credentials expire, run `scripts/deploy.sh`, what `CLOUDFRONT_DOMAIN` placeholder to use on first deploy). Keep the rest.
4. `docs/pitch/DEMO_SCRIPT.md`: a 3-minute demo, timed beats: problem (small sites shipped without basic security) → load the demo shop (`/api/scans/demo`) → findings with severity → generate fixes → show one diff and the diff guard → approve two → score rises → download patched files + `SIIDEKICK_LOG.md` with revert line → AWS architecture in one sentence. Say what to click and what to say.
5. `docs/pitch/PITCH.md`: one page. Problem, who it is for (Indian students, small shops and colleges shipping sites without a security engineer), what it does, why it is safe (never deletes owner code, diff guard, owner approves each fix, runs no uploaded code), AWS services used and why they are free tier, what is next (Phase 2 from the scope doc's non-goals).
6. `docs/pitch/SUBMISSION.md`: a fill-in form for the hackathon submission: title, one-line pitch, 150-word description, tech stack, AWS services, repo link `https://github.com/forstudies506-pixel/Siidekick`, demo video link `TODO(team)`, team names `TODO(team)`.

Writing rules: no statistics, user counts or results we have not measured; never "unhackable" or "100% secure", say "risk reduced"; plain English, short sentences; no marketing filler.

Done when the six files exist, `node -e "require('fs').readFileSync('infra/template.yaml','utf8')"` runs, and `grep -c ExistingRoleArn infra/template.yaml` is at least 3.
